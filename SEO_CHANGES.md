## July 22, 2026 — 04:33 UTC — City Page Merchant Listing Fix

### Changes Made

#### 7. Fixed City Page "Missing field image" Merchant Listing Error
**File:** `frontend/src/app/[countryCode]/(main)/city/[citySlug]/page.tsx`
- **Problem:** City pages (/in/city/ahmedabad, /in/city/bangalore, /in/city/pune etc.) had a `Product` schema inside `hasOfferCatalog.itemListElement[0].itemOffered` that was (a) missing required `image` field, (b) had invalid `price: "0.00"`, (c) pointed to `/products/petha` — a URL that doesn't exist as a product handle.
- **Fix:** Changed `itemOffered` from `@type: "Product"` to `@type: "Service"`. City pages are delivery service landing pages, not product pages — Service is the semantically correct type and won't trigger invalid merchant listing warnings.
- **Impact:** Removes 3 invalid merchant listing items from GSC. City pages now correctly described as delivery services.

### Changes Made

#### 1. Removed Duplicate Product Schemas (CRITICAL)
**Files:** `frontend/src/modules/products/templates/index.tsx`, `frontend/src/app/[countryCode]/(main)/products/[handle]/page.tsx`
- **Problem:** Every product page had 3 competing schema entities (JSON-LD from page.tsx, JSON-LD from generateProductSchema, and HTML Microdata from template) → Google showed "multiple aggregate ratings", 10 invalid review snippets, 2 invalid merchant listings
- **Fix:** Removed Schema C (inline JSON-LD from page.tsx) and Schema B (all HTML Microdata from template). Only Schema A (generateProductSchema in @lib/seo) remains.
- **Impact:** Product snippets, merchant listings, and review snippets should all go from invalid → valid after next crawl.

#### 2. Fixed Homepage Price Bug (CRITICAL)
**File:** `frontend/src/app/[countryCode]/(main)/page.tsx`
- **Problem:** `computed_amount` is already in INR major units, but was being divided by 100 → ₹299 showed as ₹2.99 in Google's rich results
- **Fix:** Removed the `/100` from `calculated_amount` path. The `prices[].amount` fallback still correctly divides by 100 (it's in paise).
- **Impact:** Google merchant listings will show correct prices.

#### 3. Fixed Categories Page Soft 404 (CRITICAL)
**File:** `frontend/src/app/[countryCode]/(main)/categories/page.tsx`
- **Problem:** `if (!categories)` check passes when Medusa returns empty array `[]` (truthy in JS). Page rendered "Browse Categories" heading with no content → Google classified as Soft 404.
- **Fix:** Changed to `if (!categories || categories.length === 0)` → now returns proper 404 when no categories.
- **Impact:** Removes /in/categories Soft 404 from GSC.

#### 4. Added `validFrom` to All Product Offer Schemas (NON-CRITICAL)
**Files:** `frontend/src/lib/seo/index.ts`, `frontend/src/app/[countryCode]/(main)/page.tsx`
- **Problem:** GSC showed "Missing field 'validFrom'" warning on every product.
- **Fix:** Added `"validFrom": new Date().toISOString().split('T')[0]` to all Offer schema blocks.
- **Impact:** Removes all non-critical warnings from GSC Rich Results report.

#### 5. Added `shippingDetails` + `hasMerchantReturnPolicy` to Homepage Schema (NON-CRITICAL)
**File:** `frontend/src/app/[countryCode]/(main)/page.tsx`
- **Problem:** Homepage product offer schemas were missing these fields that the product page schemas had.
- **Fix:** Added full `shippingDetails` and `hasMerchantReturnPolicy` objects to each product offer in `hasOfferCatalog`.
- **Impact:** Homepage products fully eligible for merchant listings rich results.

#### 6. Fixed Sitemap Exclusion Patterns
**File:** `frontend/next-sitemap.js`
- **Problem:** Exclusion patterns like `/forgot-password` only matched the root path, NOT `/in/forgot-password` generated by the `[countryCode]` dynamic route. Auth and search pages were leaking into sitemap.
- **Fix:** Added `*/` wildcard prefix versions of all exclusion patterns (e.g. `/*/forgot-password`, `/*/reset-password`, `/*/search/*`).
- **Impact:** Auth pages and search pages will be excluded from sitemap on next build.
